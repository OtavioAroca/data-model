📊 Modelagem de Dados

Catálogo V0 de Produtos de Dados — Domínio Cartão

O que é este catálogo?

Uma proposta de modelagem de dados para o domínio de cartão de crédito, organizada em torno de três conceitos-chave:

Domain-Driven Design (DDD)

Organiza o domínio em bounded contexts (subdomínios autônomos) e os classifica por importância estratégica: Core (diferencial competitivo), Support (necessário mas não diferencial), Generic (soluções off-the-shelf).

Camada Medalhão

Estrutura o data lake em Bronze (dados brutos), Silver (limpo e padronizado, com L1/L2), Gold (pronto para consumo). Silver L1 preserva histórico completo; Silver L2 materializa estado atual via regra de negócio.

Core / Integration / Analytics

Classifica os produtos de dados por escopo: Core (1 bounded context), Integration (cruza ≥2 contextos), Analytics (moldado para caso de uso final). São eixos independentes dos anteriores.

Por que Produtos de Dados?

Benefícios de adotar esta abordagem de modelagem de dados:

🎯 Alinhamento com Negócio

Organizar por bounded contexts (subdomínios) espelha as estruturas de negócio. Cada time de domínio "possui" seus dados e toma decisões de design.

🔍 Transparência de Dados

O catálogo centralizado documenta o que existe, quem é o dono, quem consome, em que camada está. Reduz silos e acelera descoberta de dados.

💾 Eficiência Silver L1 ≠ L2

Manter L1 (histórico completo) e L2 (estado atual) separados economiza custo de reprocessamento: Analytics lê L1 quando precisa de múltiplos timestamps; Integration lê L2 (estado atual) para operações. Não é redundância, é otimização por audiência.

🔗 Integration reduz N×N

Um produto Integration cruza múltiplos bounded contexts e padroniza schema. Sem ele, cada consumidor teria que cruzar N contextos de forma independente — criando N×M integrations ao invés de 1+M.

🌍 Analytics em Português

Usar nomes em português nos produtos Analytics (não em inglês como Core/Integration) reduz fricção com consumidores não-técnicos (Risk, Marketing, Finance). Menos tradução mental.

📈 Escalabilidade Organizacional

À medida que o catálogo cresce, a estrutura "catálogo modular por subdomínio" permite que novos times de domínio se integrem sem reescrever tudo — apenas adicionam sua pasta catalog/<slug>/ e seus produtos.
